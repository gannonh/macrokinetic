# Task 001: SwiftData Models - DoseSchedule, ScheduledDose, DoseEvent

## Description

Create the foundational SwiftData models for the dose scheduling system. This includes the persistent models (`DoseSchedule`, `ScheduledDose`) and a calculated entity (`DoseEvent`) that combines scheduled and actual doses for unified timeline presentation.

These models follow the established SwiftData + CloudKit patterns with non-optional defaults, proper relationship configuration, and audit trail fields. The architecture supports flexible scheduling patterns (weekly, split-dose, custom) while maintaining medical accuracy and data integrity.

## Technical Details

### DoseSchedule Schema
```swift
@Model
final class DoseSchedule {
    var id: UUID = UUID()
    var medicationProfile: MedicationProfile?
    var patternType: SchedulePatternType = .weekly
    var baseSchedule: Data = Data() // Encoded JSON of base pattern
    var isActive: Bool = true
    var pausedAt: Date?
    var pausedUntil: Date?
    var customScheduleData: Data?
    var createdAt: Date = Date()
    var updatedAt: Date = Date()

    @Relationship(deleteRule: .cascade, inverse: \ScheduledDose.schedule)
    var scheduledDoses: [ScheduledDose] = []

    var nextScheduledDose: Date? {
        // Find earliest pending ScheduledDose
    }
}

enum SchedulePatternType: String, Codable {
    case weekly       // Standard weekly doses (e.g., semaglutide)
    case splitDose    // Split single dose into multiple injections
    case custom       // Custom recurring pattern
}
```

### ScheduledDose Schema
```swift
@Model
final class ScheduledDose {
    var id: UUID = UUID()
    var schedule: DoseSchedule?
    var scheduledTime: Date = Date()
    var doseAmount: Double = 0.0
    var windowStart: Date = Date()
    var windowEnd: Date = Date()
    var actualDose: Dose?
    var skippedAt: Date?
    var skipReason: String?
    var rescheduledFrom: Date?
    var createdAt: Date = Date()
    var updatedAt: Date = Date()

    var isInWindow: Bool {
        let now = Date()
        return now >= windowStart && now <= windowEnd
    }

    var status: ScheduledDoseStatus {
        // Logic: taken if actualDose exists, skipped if skippedAt exists, missed if past windowEnd, else pending
    }
}

enum ScheduledDoseStatus: String, Codable {
    case pending
    case taken
    case skipped
    case missed
}
```

### DoseEvent Struct
```swift
struct DoseEvent: Identifiable, Comparable {
    let id: UUID
    let timestamp: Date
    let type: DoseEventType
    let scheduledDose: ScheduledDose?
    let actualDose: Dose?
    let doseAmount: Double
    let adherenceStatus: AdherenceStatus

    var isAdherent: Bool {
        adherenceStatus == .adherent
    }

    static func from(scheduledDose: ScheduledDose) -> DoseEvent { ... }
    static func from(actualDose: Dose) -> DoseEvent { ... }
    static func combined(scheduled: ScheduledDose, actual: Dose) -> DoseEvent { ... }

    static func < (lhs: DoseEvent, rhs: DoseEvent) -> Bool {
        lhs.timestamp < rhs.timestamp
    }
}

enum DoseEventType: String, Codable {
    case scheduled
    case taken
    case skipped
    case missed
}

enum AdherenceStatus: String, Codable {
    case adherent
    case nonAdherent
    case pending
}
```

### Integration Points
- **MedicationProfile Extension**: Add `schedules` relationship for managing multiple schedule patterns per medication
- **Dose Extension**: Add `scheduledDose` reference to link actual doses to their scheduled counterparts
- **CloudKit Sync**: All fields use CloudKit-compatible types (UUID, Date, Double, String, Data, Bool)
- **Audit Trail**: `createdAt` and `updatedAt` timestamps on all persistent models for debugging and sync tracking

### Medical Accuracy Considerations
- **Scheduling Windows**: `windowStart` and `windowEnd` define adherence window (typically ±2 hours for weekly doses)
- **Pause/Resume**: `pausedAt` and `pausedUntil` support treatment interruptions without losing schedule history
- **Reschedule Tracking**: `rescheduledFrom` preserves original scheduled time for adherence analysis
- **Skip Reasons**: Optional `skipReason` field enables tracking of intentional vs missed doses
- **Dose Amount Tracking**: `doseAmount` on ScheduledDose supports dose escalation scenarios
