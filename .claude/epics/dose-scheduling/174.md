# Task 001: SwiftData Models - DoseSchedule, ScheduledDose, DoseEvent

## Description

Create the foundational SwiftData models for the dose scheduling system. This includes the persistent models (`DoseSchedule`, `ScheduledDose`) and a calculated entity (`DoseEvent`) that combines scheduled and actual doses for unified timeline presentation.

These models follow the established SwiftData + CloudKit patterns with non-optional defaults, proper relationship configuration, and audit trail fields. The architecture supports flexible scheduling patterns (weekly, split-dose, custom) while maintaining medical accuracy and data integrity.

### DoseSchedule Schema
```swift
@Model
final class DoseSchedule {
    var id: UUID = UUID()
    var medicationProfile: MedicationProfile?
    var patternType: SchedulePatternType = .weekly
    var baseSchedule: Data = Data() // Encoded JSON of base pattern
    var isActive: Bool = true
    var pausedAt: Date?
    var pausedUntil: Date?
    var customScheduleData: Data?
    var createdAt: Date = Date()
    var updatedAt: Date = Date()

    @Relationship(deleteRule: .cascade, inverse: \ScheduledDose.schedule)
    var scheduledDoses: [ScheduledDose] = []

    var nextScheduledDose: Date? {
        // Find earliest pending ScheduledDose
    }
}

enum SchedulePatternType: String, Codable {
    case weekly       // Standard weekly doses (e.g., semaglutide)
    case splitDose    // Split single dose into multiple injections
    case custom       // Custom recurring pattern
}
```

### ScheduledDose Schema
```swift
@Model
final class ScheduledDose {
    var id: UUID = UUID()
    var schedule: DoseSchedule?
    var scheduledTime: Date = Date()
    var doseAmount: Double = 0.0
    var windowStart: Date = Date()
    var windowEnd: Date = Date()
    var actualDose: Dose?
    var skippedAt: Date?
    var skipReason: String?
    var rescheduledFrom: Date?
    var createdAt: Date = Date()
    var updatedAt: Date = Date()

    var isInWindow: Bool {
        let now = Date()
        return now >= windowStart && now <= windowEnd
    }

    var status: ScheduledDoseStatus {
        // Logic: taken if actualDose exists, skipped if skippedAt exists, missed if past windowEnd, else pending
    }
}

enum ScheduledDoseStatus: String, Codable {
    case pending
    case taken
    case skipped
    case missed
}
```

### DoseEvent Struct
```swift
struct DoseEvent: Identifiable, Comparable {
    let id: UUID
    let timestamp: Date
    let type: DoseEventType
    let scheduledDose: ScheduledDose?
    let actualDose: Dose?
    let doseAmount: Double
    let adherenceStatus: AdherenceStatus

    var isAdherent: Bool {
        adherenceStatus == .adherent
    }

    static func from(scheduledDose: ScheduledDose) -> DoseEvent { ... }
    static func from(actualDose: Dose) -> DoseEvent { ... }
    static func combined(scheduled: ScheduledDose, actual: Dose) -> DoseEvent { ... }

    static func < (lhs: DoseEvent, rhs: DoseEvent) -> Bool {
        lhs.timestamp < rhs.timestamp
    }
}

enum DoseEventType: String, Codable {
    case scheduled
    case taken
    case skipped
    case missed
}

enum AdherenceStatus: String, Codable {
    case adherent
    case nonAdherent
    case pending
}
```

## Learnings & Knowledge Capture

### Technical Patterns → system-patterns.md
- **CloudKit Relationship Requirements**: All SwiftData relationships must be optional for CloudKit sync, and parent side must use `@Relationship(inverse:)` while child side uses plain property
- **One-Side Relationship Rule**: Never add `@Relationship` to both sides - causes "Circular reference resolving attached macro" error
- **SwiftData Relationship Assignment Order**: Insert all objects into context BEFORE setting relationships to avoid "Duplicate registration attempt" crashes
- **Computed Property Timing Precision**: When comparing `Date()` to stored dates, add small tolerance (1 second) for boundary conditions to handle millisecond-level timing variations in tests

### Technology Insights → tech-context.md
- **SwiftData Test Anti-Pattern**: Fixed systematic issue of incomplete ModelConfiguration in tests - must include ALL models and `cloudKitDatabase: .none` for proper test isolation
- **Coverage Testing Patterns**: Uncovered closures in computed properties require specific test scenarios that exercise the closure code paths (filter, min, etc.)
- **Parallel Stream Development Success**: 4 streams completed simultaneously with no conflicts - proper file ownership and coordination prevents merge issues

### Process Insights → progress.md
- **Systematic Bug Fixing**: User request to "find anti-patterns systemically" led to discovering ModelConfiguration issue across multiple test files - better than one-by-one fixes
- **Test-Driven Bug Discovery**: Failing tests after integration revealed 3 distinct bug categories (schema counts, logic errors, boundary conditions) - systematic categorization helps prioritize fixes

### Product Insights → product-context.md
- **Medical Adherence Definition**: Adherence means actually taking medication, not just having a valid reason to skip - `isAdherent` should return false for skipped doses even if they have `.adherent` status
- **Scheduling Window Tolerances**: 1-second tolerance on dose timing windows is medically reasonable and necessary for system reliability with real-world timing precision

### Project Structure → project-structure.md
- **SwiftData Model Location**: All persistent models in `JabTracker/Models/`, calculated entities (like DoseEvent struct) also in same directory for discoverability
- **Test File Organization**: Model tests follow parallel structure - `DoseSchedule.swift` → `DoseScheduleTests.swift`
