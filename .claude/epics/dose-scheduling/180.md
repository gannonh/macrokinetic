# Fix Split-Dose Medical Accuracy & Add Medication-Specific Patterns

## Objective
Fix critical medical accuracy issues in split-dose implementation where weekly medications incorrectly default to twice-daily dosing instead of twice-weekly dosing. Add medication-specific pattern filtering so daily medications don't offer split-dose as an option.

## Critical Problems Identified

### ❌ Problem #1: Medically Incorrect Interval (CRITICAL)
**Current Behavior:**
- Split-dose uses `splitIntervalMinutes: 720` (12 hours)
- Suggests twice DAILY dosing for weekly medications
- UI shows "Interval: 1 day" for split-dose

**Expected Behavior for Weekly Medications:**
- Semaglutide 0.25mg weekly → Split: 0.125mg twice weekly
- Interval: 3.5 days (84 hours / 5040 minutes)
- Example pattern: Wednesday evening 0.125mg + Sunday morning 0.125mg

**Files Affected:**
- `JabTracker/Onboarding/OnboardingViewModel.swift` (line ~180)
- `JabTracker/Views/Settings/DoseScheduleEditView.swift` (line ~200)

### ❌ Problem #2: Misleading UI Description
**Current Text:**
```
"Multiple doses per day (e.g., morning and evening)"
```

**This is medically dangerous** - users could accidentally overdose weekly medications by taking them daily!

**Correct Text Should Be:**
```
"Divide weekly dose into two administrations (e.g., Wednesday and Sunday)"
```

**Files Affected:**
- `JabTracker/Views/Settings/DoseScheduleEditView.swift` (patternFooterText)
- `JabTracker/Onboarding/Components/SchedulePatternCard.swift` (description)

### ❌ Problem #3: No Medication-Specific Filtering
**Current Behavior:**
- Split-dose offered to ALL medications regardless of frequency

**Expected Behavior:**
- ✅ Show split-dose for weekly medications:
  - Semaglutide, Tirzepatide, Dulaglutide
- ❌ Hide split-dose for daily medications:
  - Liraglutide (already daily, cannot split further)

**Solution:**
- Use existing `Medication.frequency` property to filter patterns
- Only show split-dose option when `medication.frequency == .weekly`

### ❌ Problem #4: Confusing Interval Display
**Current Behavior:**
- Shows "7 days" or "1 day" when split-dose selected
- Doesn't clearly communicate twice-weekly pattern

**Expected Behavior:**
- Show "3.5 days" as interval
- OR show "Twice weekly" as frequency descriptor
- Make it crystal clear this is NOT daily dosing

### ❌ Problem #5: Custom Pattern Placeholder
**Current Behavior:**
- Custom pattern selectable but no configuration UI
- Shows "Coming Soon" message
- Confuses users with non-functional option

**Solution:**
- **REMOVE Custom pattern option entirely**
- Can add back later if user demand warrants it

## Technical Implementation

### 1. Fix Split-Dose Interval Calculation

**File:** `JabTracker/Services/ScheduleService.swift` or extension

Add medication-aware split-dose configuration:
```swift
extension ScheduleConfiguration {
    /// Create split-dose configuration for weekly medication
    /// - Parameters:
    ///   - medication: Medication to configure (must be weekly)
    ///   - totalWeeklyDose: Total weekly dose amount
    /// - Returns: Configuration with twice-weekly split pattern
    static func splitDoseConfiguration(
        for medication: Medication,
        totalWeeklyDose: Double
    ) throws -> ScheduleConfiguration {
        guard medication.frequency == .weekly else {
            throw ScheduleConfigurationError.splitDoseNotSupported(
                "Split-dose only supported for weekly medications"
            )
        }

        return ScheduleConfiguration(
            dayOfWeek: nil,  // Not used for split-dose
            timeOfDay: TimeComponents(hour: 8, minute: 0),
            interval: 7,  // Still weekly cycle
            windowMinutesBefore: TimeConstants.defaultWindowMinutes,
            windowMinutesAfter: TimeConstants.defaultWindowMinutes,
            splitDoseCount: 2,
            splitIntervalMinutes: 5040,  // 3.5 days = 84 hours
            customRecurrence: nil
        )
    }
}
```

### 3. Add Medication-Aware Pattern Filtering

**File:** `JabTracker/Onboarding/Components/SchedulePatternPicker.swift`

Update to accept medication parameter:
```swift
struct SchedulePatternPicker: View {
    @Binding var selectedPattern: SchedulePatternType
    let medication: Medication  // ADD THIS
    let onPatternChange: (SchedulePatternType) -> Void

    var availablePatterns: [SchedulePatternType] {
        switch medication.frequency {
        case .daily:
            return [.weekly]  // Daily meds can't split further
        case .weekly:
            return [.weekly, .splitDose]  // Weekly meds can split
        }
    }

    var body: some View {
        VStack(spacing: 12) {
            ForEach(availablePatterns, id: \.self) { pattern in
                SchedulePatternCard(
                    pattern: pattern,
                    isSelected: selectedPattern == pattern,
                    onSelect: {
                        selectedPattern = pattern
                        onPatternChange(pattern)
                    }
                )
            }
        }
    }
}
```

## Implementation Notes

### Medical Accuracy Considerations
1. **Twice Weekly ≠ Twice Daily**: This is the critical fix
2. **3.5 Day Spacing**: Standard medical practice for weekly split-dose
3. **Example Pattern**: Wednesday 8pm + Sunday 8am = ~84 hours apart
4. **Total Dose Conservation**: 0.125mg × 2 = 0.25mg weekly (no change in total)

### Backward Compatibility
- Existing schedules with `pattern: .custom` should continue to work
- Keep enum case but hide from UI
- Future implementation can re-enable if needed

### Edge Cases
1. **Existing Custom Schedules**: If any users have custom patterns, they remain functional
2. **Migration**: No data migration needed - just UI changes
3. **CloudKit Sync**: Pattern type still syncs correctly

## Learnings & Knowledge Capture

### Technical Patterns → system-patterns.md
- **E2E Test Design Pattern**: Tests must validate the actual behavior being tested, not tangential effects
  - Example: Split-dose scheduling bug is about **schedule generation intervals** (3.5 days vs 12 hours)
  - NOT about concentration calculations (which are based on historical doses, not future schedules)
  - Removed Test 4 because it tested concentration after creating a schedule, but schedules don't affect current concentration

### Process Insights → progress.md
- **Test Logic Validation**: When test fails or seems flawed, question the fundamental test logic before debugging
  - User correctly identified: "How does configuring split doses for the future effect current concentration levels?"
  - The test was testing the wrong thing entirely - important to identify and remove invalid tests
  - Better to have 3 valid tests than 4 tests where 1 is fundamentally flawed

### Product Insights → product-context.md
- **Issue #180 Medical Accuracy**: The split-dose bug is a **scheduling** issue (wrong interval generation), not a pharmacokinetic calculation issue
  - Split-dose was generating doses at 12-hour intervals (twice-DAILY) instead of 3.5-day intervals (twice-WEEKLY)
  - This is a critical medical safety issue - patients could overdose if they followed twice-daily schedule for weekly medication
  - Concentration calculations work correctly - they calculate from historical doses already taken
  - Future scheduled doses do NOT affect current concentration calculations (PK engine looks at dose history, not schedule configuration)
