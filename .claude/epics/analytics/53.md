## Learnings & Knowledge Capture

### Technical Patterns → system-patterns.md
- **SwiftData Relationship Testing Pattern**: Must insert parent entities (User, MedicationProfile) BEFORE child entities (Dose) to prevent duplicate registration crashes
- **Test Container Setup**: Use DataController.testContainer() consistently instead of creating custom ModelContainers
- **Relationship Management**: Let SwiftData handle inverse relationships automatically via property setters, never manually assign arrays

### Technology Insights → tech-context.md
- **SwiftData Auto-Insert Behavior**: SwiftData automatically inserts related entities when they're referenced, causing crashes if manually inserted afterward
- **CloudKit Compatibility**: All analytics fields must have non-optional defaults for CloudKit sync
- **Computed Properties**: Leverage SwiftData relationships for complex analytics calculations without storing derived data

### Process Insights → progress.md
- **Parallel Stream Coordination**: Three agents successfully worked on separate model extensions simultaneously without conflicts
- **TDD Approach**: Writing tests first revealed SwiftData relationship issues early
- **Systematic Debugging**: Running tests individually helped isolate crash patterns

### Product Insights → product-context.md
- **Analytics Requirements**: Adherence tracking, streak calculations, and effectiveness scoring are core analytics features
- **User Privacy**: Analytics preferences with sensible defaults respect user control over data collection

### Project Structure → project-structure.md
- **Test Organization**: One test file per model for analytics extensions keeps tests focused and maintainable
- **Model Extensions**: Computed properties in extensions keep models clean while adding analytics capabilities
