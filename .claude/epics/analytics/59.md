## Learnings & Knowledge Capture

### Product Insights → product-context.md
- **Medical App Design Standards**: Healthcare apps require therapeutic range visualization on concentration charts - critical for clinical value and helping users understand if medication levels are optimal
- **Medical Data Presentation**: Charts displaying medical data must include axis labels with units (ng/mL) - ambiguous data is misleading and reduces credibility
- **User Education Requirements**: Medical terminology like "Concentration" needs contextual help or tooltips - non-medical users may not understand "Medication Level in Your Body"
- **Motivational Design Elements**: Gamification through streak visualization (🔥 icons) increases user engagement and adherence motivation
- **Actionable Insights Value**: Users highly value specific, actionable insights (e.g., "Sunday missed doses" with reminder suggestion) over generic feedback

### Tech Insights → tech-context.md
- **iOS HIG Compliance Patterns**: Segmented controls should show selected state with clear visual feedback - standard iOS pattern expectations
- **Accessibility Requirements**: All touch targets must meet 44×44pt minimum, VoiceOver labels should describe chart trends ("improving from 60% to 100%"), color coding needs text/icon backup
- **Performance Baselines**: Analytics navigation 500-2000ms acceptable but could optimize to <500ms with skeleton loading states
- **Chart Rendering Standards**: Medical app charts should render <500ms for 365+ dose datasets, consider progressive rendering for larger datasets

### System Patterns → system-patterns.md
- **Design Review Process**: Systematic UI/UX review after E2E screenshot capture enables data-driven design decisions and before/after comparisons
- **Phase-Based Development**: Phase 1 (screenshots) → Phase 2 (analysis) → Phase 3 (implementation) → Phase 4 (optimization) provides clear checkpoints
- **Priority-Based Implementation**: Must Have (5) → Should Have (6) → Nice to Have (7) prioritization framework for polish tasks
- **Visual Baseline Documentation**: Screenshots with comprehensive analysis provide clear communication tool for design decisions and implementation guidance

### Process Insights → progress.md
- **Screenshot-Driven Design Reviews**: Capturing comprehensive E2E test screenshots enables thorough visual analysis without running simulators repeatedly
- **Design Feedback Structure**: Organizing feedback by view (above fold, below fold, specific features) with ratings and structured improvements creates actionable implementation plan
- **Cross-Cutting Concerns Analysis**: Analyzing accessibility, performance, and consistency across all views reveals systemic issues vs component-specific problems
- **Documentation Completeness**: Including Executive Summary, Priority Issues, Recommendations Summary, and Next Steps makes design review immediately actionable

### 2025-10-01 Session Update - Phase 6: Chart Time Range Bug Discovery

**Work Completed:**
- 🔍 Started Phase 6: State & Performance Optimization
- 🐛 Discovered critical chart time range filtering bug
- 📊 Analyzed console logs to identify root cause
- ⚙️ Attempted fix with .onChange and chartState updates

**Critical Bugs Identified:**
1. **7d view shows only 1 point** - No horizontal line visible, just single green dot
   - Root cause: Only 1 dose within 7-day window (correct behavior, but poor UX)
   - Console: Fetches 1 dose, generates 1 point
2. **90d and 1y views show only 30 days of data** despite correct labels (Last Quarter, Last Year)
   - Root cause: ConcentrationTimelineChart filtering points by `configuration.timeRange` in computed property
   - Console: All periods fetch 5 doses, generate ~2485 points, but UI filters incorrectly
3. **No loading UI feedback** - Charts load in background, then abruptly switch
   - User experience: "UI does not switch to 90d view and then load, it loads in the background with no indication and then switches ui when the loading is done"
4. **Loading times no longer logged** - Performance instrumentation removed from AnalyticsView

**Files Modified:**
- `JabTracker/Views/Analytics/ConcentrationTimelineChart.swift`
  - Added `.onChange(of: dataset.configuration.timeRange)` to update chartState when time period changes
  - Modified `processedConcentrationPoints` and `processedDoseMarkers` to filter by current time range
- `JabTracker/Models/ChartData.swift`
  - Added `Hashable` conformance to `TimeRange` enum to enable .onChange detection
- `JabTracker/Services/ChartDatasetService.swift`
  - Logging still present but not appearing in AnalyticsView output

**Console Log Analysis:**
```
7d:  Fetched 1 dose  → Generated 1 point   → Chart shows 1 dot (correct but poor UX)
30d: Fetched 5 doses → Generated 2485 points → Chart shows ~30 days (correct)
90d: Fetched 5 doses → Generated 2485 points → Chart shows ~30 days (BUG - should show 90 days)
1y:  Fetched 5 doses → Generated 2486 points → Chart shows ~30 days (BUG - should show 1 year)
```

**Root Cause Analysis:**
The chart dataset generation is working correctly (creating 2485+ points covering full time range), but `ConcentrationTimelineChart.processedConcentrationPoints` filters points based on `configuration.timeRange.dateRange()`. When time period changes, the dataset is regenerated with correct points, but the chart's configuration.timeRange isn't being updated, causing it to continue filtering with the old time range (30 days).
