# History List View

## Overview
Build a comprehensive dose history list view with swipe actions for editing and deleting doses, search functionality, and filtering options to provide users with easy access to their dose tracking data.

## Requirements

### Core Functionality
- List view displaying dose history in reverse chronological order
- Swipe actions for edit and delete operations
- Search functionality across dose data
- Filtering by date range, medication, and injection site
- Pull-to-refresh for data updates
- Empty state when no doses exist

### List Item Display
- **Primary Info**: Dose amount, medication name, timestamp
- **Secondary Info**: Injection site, notes preview
- **Visual Indicators**: Photo attachment icon, skipped dose styling
- **Grouping**: Group by date with section headers
- **Accessibility**: Full VoiceOver support

### Swipe Actions
- **Edit**: Navigate to dose entry form pre-populated with dose data
- **Delete**: Confirmation alert with destructive action
- **Mark as Skipped**: Toggle skipped status
- **Duplicate**: Create new dose with same data but current timestamp

### Search & Filtering
- Search bar with live filtering
- Filter by medication type
- Date range picker for temporal filtering
- Injection site filtering
- Clear filters action

## Technical Implementation

### Files to Create
- `DoseHistoryView.swift` - Main history list container
- `DoseHistoryRow.swift` - Individual dose list item
- `DoseHistoryViewModel.swift` - Business logic and data management
- `DoseSearchAndFilterView.swift` - Search and filter controls

### Files to Modify
- `HistoryView.swift` - Integrate with history list view
- `DoseEntrySheet.swift` - Support edit mode with pre-populated data

### SwiftData Integration
- Fetch doses with proper sorting and filtering
- Handle delete operations with cascade rules
- Update dose entities for edit operations
- Batch operations for performance

### Search Implementation
- Full-text search across dose notes
- Medication name matching
- Date range queries
- Compound filtering with multiple criteria

## Learnings & Knowledge Capture

### Technical Patterns → system-patterns.md
- **SwiftData Relationship Testing**: Critical pattern for tests accessing relationships (dose.medication, user.doses) - must use proper ModelContainer with CloudKit disabled
- **Test Container Setup**: ModelConfiguration with `isStoredInMemoryOnly: true, cloudKitDatabase: .none` prevents CloudKit relationship validation errors
- **Context Management**: Always insert models into context BEFORE setting relationships, then save context

### Technology Insights → tech-context.md  
- **CloudKit vs Testing**: CloudKit requires all relationships to have proper inverses, but tests should disable CloudKit entirely
- **SwiftData Testing**: Raw model creation without ModelContext causes crashes when accessing relationships
- **Test Environment Detection**: DataController properly detects test environment and disables CloudKit automatically

### Process Insights → progress.md
- **Debugging Approach**: "Executed 0 tests" in test output indicates app crash during test setup, not missing test targets
- **Testing Infrastructure**: Establishing proper test patterns early prevents widespread test failures later

- **Element Targeting Debug-First**: When E2E tests fail to find elements, ALWAYS start with TestUtilities.debugElements() to reveal actual accessibility hierarchy
- **Systematic Problem Solving**: 5-step process (debug → analyze → update → clean → document) prevents repeated element targeting issues
