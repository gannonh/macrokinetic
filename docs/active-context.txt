 The Problem

  When we delete a MedicationProfile, the cascade delete on line 30-31 of MedicationProfile.swift:

  @Relationship(deleteRule: .cascade, inverse: \Dose.medication)
  var doses: [Dose]?  // CloudKit requires optional relationships

  This deletes all historical doses (the actual taken doses), which destroys all analytics data and medication history. That's not what users
  want!

  Your Proposed Solution is Perfect ✅

  Two-action approach:
  1. "Disable" (soft delete) - Default/recommended action
    - Sets isActive = false on the medication profile
    - Preserves all historical data and analytics
    - Hides from active medication lists
    - Can be re-enabled later
  2. "Delete" (hard delete) - Destructive action with warning
    - Shows confirmation dialog: "This will permanently delete all dose history and analytics for this medication. Consider disabling instead
  to preserve your data."
    - Only for users who truly want to remove everything

  Implementation Plan

  1. Add isActive field to MedicationProfile (if not already present)
  2. Change cascade delete rule for doses from .cascade to .nullify
  3. Update deletion UI:
    - Change swipe action to "Disable" by default
    - Add "Delete Permanently..." option with warning dialog
  4. Filter queries to exclude disabled profiles from active lists
  5. Add E2E test to verify:
    - Deleting profile removes scheduled doses ✓
    - Deleting profile does NOT remove historical doses ✓
    - Disabling profile preserves everything ✓

  Should I proceed with this implementation? This is a much better UX and prevents accidental data loss!
