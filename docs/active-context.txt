 Fix Reconstitution Calculator Integration Issues

    Issues Identified

    1. NavigationLink Problem: Detail view uses NavigationLink but calculator 
    can't save when accessed this way (no onSave callback)
    2. Default Water Volume: Inconsistent - Edit view defaults to 10ml instead of
     1ml
    3. Code Duplication: Significant duplication between Add and Edit views for 
    calculator sheet presentation
    4. Missing Save Button: NavigationLink presentation doesn't provide save 
    functionality

    Proposed Solution

    1. Fix NavigationLink in Detail View

    - Change from NavigationLink to a button that opens calculator as sheet (like
     Add view)
    - This ensures consistent behavior and proper save functionality

    2. Fix Default Water Volume

    - Change default from 10ml to 1ml in both:
      - EditMedicationProfileView initialization (line 467)
      - ReconstitutionCalculatorView profile fallback (line 41)

    3. Create Shared Calculator Sheet Component

    - Extract duplicate sheet presentation code into reusable component
    - Create ReconstitutionCalculatorSheet that handles:
      - Sheet presentation binding
      - onSave callback with concentration/units calculation
      - Consistent defaults (1ml water volume)

    4. Update All Three Views

    - MedicationProfileDetailView: Replace NavigationLink with button + sheet
    - AddMedicationProfileView: Use new shared component
    - EditMedicationProfileView: Use new shared component

    Implementation Steps

    1. Create ReconstitutionCalculatorSheet component in 
    MedicationFormComponents.swift
    2. Update MedicationProfileDetailView to use sheet instead of NavigationLink
    3. Replace duplicate sheet code in Add and Edit views with shared component
    4. Fix default water volume to 1ml everywhere
    5. Test all three access paths to ensure save functionality works

    Benefits

    - DRY Principle: Single source of truth for calculator presentation
    - Consistency: Same behavior across all access points
    - Maintainability: Future changes only need to be made in one place
    - User Experience: Save button always available, consistent defaults
