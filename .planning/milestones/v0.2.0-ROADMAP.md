# Milestone v0.2.0: Enhanced Tracking

**Status:** SHIPPED 2025-12-27
**Phases:** 5-11
**Total Plans:** 11

## Overview

Enhanced daily tracking for MacroKinetic with calendar navigation, food library management, quick macro entry, weight tracking with HealthKit sync, body metrics with progress photos, and feature settings for metrics visibility and units of measure.

## Phases

### Phase 5: Food Log Calendar

**Goal:** Week calendar navigation with day selection updating macro summary
**Depends on:** Previous milestone complete
**Plans:** 1 plan

Plans:
- [x] 05-01: Week calendar strip with day selection and shared date state

**Details:**
- Week calendar strip with horizontal scroll and day selection
- @Binding for selectedDate enabling tab bar + button to use same date
- onAppear for week initialization avoiding SwiftUI @State timing issues
- 44x44pt tap targets per Apple HIG

### Phase 6: Food Entry Editing

**Goal:** Tap food entry to open editable FoodDetailSheet
**Depends on:** Phase 5
**Plans:** 1 plan

Plans:
- [x] 06-01: Tap-to-edit food entries with E2E test coverage

**Details:**
- Button wrapper for tap-to-edit with better VoiceOver accessibility
- E2E tests create own data for reliability
- Reused existing FoodDetailSheet for consistency

### Phase 7: Food Library

**Goal:** Dedicated Food Library screen with Foods tab, sort options, tap-to-add
**Depends on:** Phase 6
**Plans:** 1 plan

Plans:
- [x] 07-01: Food Library content with tabs, sort, and entry points

**Details:**
- LibraryTab enum with isEnabled for future Recipes/Favorites expansion
- Safe unwrap customFoodService with error state fallback
- Sort options for organizing food library
- Your Foods shortcut integration

### Phase 8: Quick Add

**Goal:** Macro-only food logging without food lookup
**Depends on:** Phase 7
**Plans:** 1 plan

Plans:
- [x] 08-01: Quick Add feature for macro-only food logging

**Details:**
- Quick Add as FoodSearchSheet tab for consistent UI
- Macros stored as per-100g with servingGrams=100 matching FoodEntry model
- MealSection.from(date:) respects user's selected date in Food Log

### Phase 9: Weight Tracking

**Goal:** Weight and body fat entry with HealthKit sync
**Depends on:** Phase 8
**Plans:** 3 plans

Plans:
- [x] 09-01: WeightEntry model + WeightService with HealthKit sync
- [x] 09-02: QuickWeightSheet UI and ShortcutsSheet wiring
- [x] 09-03: Unit tests and E2E test stubs

**Details:**
- Weight stored in kg internally, converted to lbs for display
- Body fat as 0-100 percentage, converts to 0-1 ratio for HealthKit
- Weight validation 20-500 kg covering reasonable human range
- QuickWeightSheet with unit conversion and HealthKit sync

### Phase 10: Metrics & Photos

**Goal:** Configurable body metrics with progress photo capture
**Depends on:** Phase 9
**Plans:** 2 plans

Plans:
- [x] 10-01: MetricsEntry + ProgressPhoto models and services with HealthKit sync
- [x] 10-02: UI Sheets + Integration (QuickMetricsSheet, QuickPhotoSheet, ShortcutsSheet wiring)

**Details:**
- Measurements stored in cm internally, converted to inches for display
- HealthKit sync for waist only (Apple Health only supports waistCircumference)
- PhotoType as String for CloudKit compatibility
- "AI" placeholder in top row shortcuts reserved for future CV macro entry
- Camera + Library buttons shown upfront for faster UX

### Phase 11: Feature Settings

**Goal:** Body metrics visibility toggles and units of measure configuration
**Depends on:** Phase 10
**Plans:** 2 plans

Plans:
- [x] 11-01: Metrics visibility preferences, BodyMetricsVisibilityView, sheet filtering
- [x] 11-02: Units of measure preferences, UnitsOfMeasureView, sheet integration

**Details:**
- Default enabledBodyMetrics to ["waist"] - most common use case
- Default enabledPhotoTypes to ["front"] - minimal default
- Users opt-in to additional metrics and photo types as needed
- Complete settings UI for body metrics visibility and units
