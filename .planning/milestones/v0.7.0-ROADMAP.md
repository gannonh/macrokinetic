# Milestone v0.7.0: Dashboard Widget UX

**Status:** SHIPPED 2026-01-12
**Phases:** 30-34 (including 33.1 inserted)
**Total Plans:** 14

## Overview

Build the new unified dashboard with widget-based UI — static mockups first, wired to data once patterns established. Delivered a complete widget ecosystem with hero carousel (3 swipeable pages), standard insights grid (4 widgets), live data integration across nutrition and expenditure tracking, and extensible detail view architecture.

## Phases

### Phase 30: Dashboard Foundation

**Goal**: Create DashboardView with widget container system, establish reusable widget card patterns
**Depends on**: v0.6.0 complete
**Plans**: 2 plans

Plans:
- [x] 30-01: Foundation & Containers (DashboardWidget protocol, WidgetCard, HeroWidgetContainer, StandardWidgetGroup)
- [x] 30-02: Hero Widget Integration (WeeklyNutritionHeroWidget with mock data, integrate into DashboardView)

**Details:**
Established DashboardWidget protocol with id, title, and content requirements. Created container components (WidgetCard, HeroWidgetContainer, StandardWidgetGroup) for consistent card styling and layout. Array-based HeroWidgetContainer init to avoid SwiftLint large_tuple violations.

### Phase 31: Main Widget (Hero)

**Goal**: Swipeable carousel with 3 states (Weekly Nutrition, Energy Balance, Daily Nutrition), Consumed/Remaining toggle
**Depends on**: Phase 30
**Plans**: 2 plans

Plans:
- [x] 31-01: Daily Nutrition Widget (DailyNutritionHeroWidget with circular ring, macro bars, environment-based toggle)
- [x] 31-02: Energy Balance Widget + Integration (EnergyBalanceHeroWidget with Swift Charts, complete carousel)

**Details:**
Implemented environment-based display mode propagation (HeroDisplayModeKey, EnergyDisplayModeKey) for shared toggle state across carousel. 130pt ring diameter (reduced from 160pt per user feedback). Day selection defaults to week totals with tap-to-drill-down UX. Carousel order: Weekly → Daily → Energy.

### Phase 32: Standard Widgets - Insights

**Goal**: Insights & Analytics widget group with Expenditure, Weight Trend, Energy Balance, Goal Progress, Deficit cards
**Depends on**: Phase 31
**Plans**: 1 plan

Plans:
- [x] 32-01: Standard Widget Components (ExpenditureWidget, WeightTrendWidget, EnergyBalanceWidget, GoalProgressWidget)

**Details:**
Built four standard grid widgets with mini Swift Charts visualizations. 2x2 StandardWidgetGroup layout integrating with hero carousel. Each widget shows compact visualization with detail view navigation.

### Phase 33: Detail Views

**Goal**: Weight Trend, Expenditure, Energy Balance detail screens with charts and time range filters
**Depends on**: Phase 32
**Plans**: 3 plans

Plans:
- [x] 33-01: Weight Trend Detail View (header, time filters, line chart, insights cards, data sources)
- [x] 33-02: Expenditure Detail View (bar chart, insights cards, shared DetailTimePeriodSelector)
- [x] 33-03: Energy Balance Detail View (mode toggle, navigation wiring from widgets)

**Details:**
Created WeightTrendDetailView with comprehensive mock data including time period filtering (1W-All + daily toggle), Swift Charts line charts with trend lines, five insight cards, and a data sources log section. Established reusable DetailTimePeriod enum for all detail views. Shared DetailTimePeriodSelector component.

## Milestone Summary

**Decimal Phases:**
- Phase 33.1: TDEE History Tracking (inserted after Phase 33 for urgent data infrastructure)

**Key Decisions:**

| Phase | Decision | Rationale |
|-------|----------|-----------|
| 30-01 | Array-based HeroWidgetContainer init | Avoid SwiftLint large_tuple violations vs ViewBuilder tuple overloads |
| 30-02 | Rectangular cells (26x38) for macro bars | Better visual hierarchy than square cells for progress visualization |
| 30-02 | Border-only today indicator | Cleaner than "T" text inside cells |
| 31-01 | Environment key for HeroDisplayMode | Cleaner than closure-based injection for shared toggle state |
| 31-01 | 130pt ring diameter (vs 160pt) | User feedback - reduced vertical cramping |
| 31-02 | EnergyDisplayMode environment key | Same pattern as HeroDisplayMode for consistency |
| 31-02 | Page-specific toggles in container | Energy Balance uses different toggle options than Weekly/Daily |
| 31-02 | Daily averages for Energy Balance | More meaningful than 30-day totals for "Last 30 Days" view |
| 31-02 | Day selection defaults to week totals | Simplest UX; tap to drill down into specific days |
| 31-02 | Carousel order: Weekly → Daily → Energy | Daily exists in carousel, Weekly should be primary |

**Issues Resolved:**
- TDEE history data gap resolved with TDEESnapshot model and backfill
- Widget state sharing solved with environment-based display modes
- Detail view consistency achieved with shared DetailTimePeriod enum

**Issues Deferred:**
- None

**Technical Debt Incurred:**
- None significant
