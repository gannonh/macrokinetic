# Milestone v0.1.0: Custom Foods

**Status:** SHIPPED 2025-12-24
**Phases:** 1-4
**Total Plans:** 6

## Overview

Add custom food creation and management to MacroKinetic, enabling users to create personalized foods from existing database entries or from scratch, with barcode scanning for quick lookup.

## Phases

### Phase 1: CustomFood Model & Storage

**Goal:** SwiftData model with CloudKit compatibility and CRUD service
**Depends on:** Nothing (first phase)
**Plans:** 1 plan

Plans:
- [x] 01-01: CustomFood model and service implementation

**Details:**
- Created CustomFoodService with create, read, update, delete operations
- Implemented validation for empty names, negative macros, invalid serving sizes
- Added barcode uniqueness checking within custom foods
- Integrated into AppServices for app-wide access
- Wired custom foods into FoodService.searchCategorized()
- Added Food.createCustom() factory and isCustomFood computed property
- 24 unit tests and 7 integration tests all passing

### Phase 2: Create Food UI

**Goal:** CreateFoodSheet for entering custom food details
**Depends on:** Phase 1
**Plans:** 2 plans

Plans:
- [x] 02-01: CreateFoodSheet UI implementation
- [x] 02-02: ViewModel and validation logic

**Details:**
- CreateFoodViewModel with @Observable pattern, Mode enum (create/edit), comprehensive validation
- CreateFoodSheet form UI with 4 sections (Basic Info, Nutrition, Serving, Barcode)
- Full accessibility identifier coverage on all interactive elements
- Prefill support from FoodSearchResult for "To Custom" flow
- "To Custom" button in FoodDetailSheet opens CreateFoodSheet with pre-filled data
- "Create & Add" button creates custom food and logs it to meal in single action

### Phase 3: Food Library Integration

**Goal:** Custom foods appear in search and can be managed
**Depends on:** Phase 2
**Plans:** 1 plan

Plans:
- [x] 03-01: Search integration and management UI

**Details:**
- Renamed "Custom" section to "My Foods" in search results
- Added swipe-left-to-edit with CreateFoodSheet integration
- Added swipe-right-to-delete with confirmation alert
- Custom foods prioritized in search results
- Created E2E test stubs covering 7 acceptance scenarios

### Phase 4: Barcode Assignment

**Goal:** Scan or manually enter barcodes for custom foods
**Depends on:** Phase 3
**Plans:** 2 plans

Plans:
- [x] 04-01: Barcode scanner implementation
- [x] 04-02: Barcode assignment and lookup

**Details:**
- CameraService with AVFoundation session and permission handling
- BarcodeScannerContentView with sub-toggle row (Barcode/Label pills), torch toggle, and scanning reticle
- AVCaptureMetadataOutput barcode detection (ean8, ean13, upce, code128, qr)
- 2-second debouncing prevents rapid-fire detection
- Lookup priority: custom foods first (local, fast), then Open Food Facts API
- ShortcutsSheet Barcode button opens scanner directly

## Milestone Summary

**Decimal Phases:**
None - all phases executed in planned order.

**Key Decisions:**

| Phase | Decision | Rationale |
|-------|----------|-----------|
| 1 | Reuse Food model with source = .userCreated | No new model needed; existing infrastructure supports custom foods |
| 1 | Barcode uniqueness within custom foods only | Database foods can share barcodes; user custom foods must be unique |
| 1 | Case-insensitive search for custom food names | Better user experience when searching |
| 3 | State variables internal instead of private | Needed for extension file access in FoodSearchSheet |
| 4 | @preconcurrency import AVFoundation | Cleanly handles Sendable warnings for AVCaptureSession |
| 4 | Label scan type disabled initially | Placeholder for future OCR/label scanning functionality |

**Issues Resolved:**
- FoodSearchResult lacking id property (auto-fixed in Phase 1)
- AVFoundation Sendable warnings (auto-fixed in Phase 4)

**Issues Deferred:**
- Manual barcode entry field (scan-only for now)
- Recipe builder (combining foods into calculated recipes)

**Technical Debt Incurred:**
None - all phases completed cleanly.
