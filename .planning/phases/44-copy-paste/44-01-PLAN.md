2. `FoodClipboardContent` enum with cases:
   - `.day(date: Date, entries: [ClipboardEntry])` - for copying entire day
   - `.meal(date: Date, meal: MealSection, entries: [ClipboardEntry])` - for copying single meal
   - Computed property `entryCount: Int` for UI display
   - Computed property `sourceDescription: String` for UI (e.g., "3 items from Breakfast")
   - Conform to Equatable

WHY this design: SwiftData model objects (FoodEntry) are tied to their ModelContext and can become invalid after navigation. Lightweight value types avoid this pitfall.

  <files>JabTracker/Services/FoodClipboardService.swift</files>
  <action>
Create FoodClipboardService.swift following project service conventions:

1. Class definition:
   - `@MainActor @Observable final class FoodClipboardService`
   - Private static logger: `Logger(subsystem: "com.gannonhall.JabTracker", category: "FoodClipboardService")`

2. Properties:
   - `private(set) var content: FoodClipboardContent?` - current clipboard content (nil = empty)
   - `var hasContent: Bool { content != nil }` - convenience for UI checks
   - `var entryCount: Int { content?.entryCount ?? 0 }` - convenience for UI display

3. Methods:
   - `func copyDay(date: Date, entries: [FoodEntry])` - converts entries to ClipboardEntry array, sets content to .day case, logs info
   - `func copyMeal(date: Date, meal: MealSection, entries: [FoodEntry])` - converts entries to ClipboardEntry array, sets content to .meal case, logs info
   - `func clear()` - sets content to nil, logs debug

4. Logging:
   - Info level for copy operations with count
   - Debug level for clear

WHY @Observable not ObservableObject: Project convention per CONVENTIONS.md, simpler state management.
WHY no persistence: COPY-05 requires session-only clipboard (cleared on app termination), so memory-only storage is correct.
  </action>
