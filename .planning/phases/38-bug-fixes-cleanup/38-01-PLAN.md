**Bug Analysis:**
1. Barcode scanner bug: `handleBarcodeDetected()` calls `foodService?.lookupBarcode()` which only queries the OpenFoodFacts API. The local database has 1.7M+ foods with barcodes but `LocalFoodDatabase.lookupBarcode()` is never called.

2. API is unnecessary: The local database contains the entire OFF dump (1.7M products). If a barcode isn't found locally, it won't be in the API either. API adds latency, complexity, and failure modes for zero benefit.

3. Dead code: `FoodSearchView.swift`, `AddFoodSheet.swift`, and `MealLogView.swift` are unused.

4. ISS-001: ShortcutButton needs `.contentShape(Rectangle())` for proper tap targets.

**Decision:**
- Remove ALL Open Food Facts API code - local database is sufficient
- If barcode not found locally, show "not found" (user can create custom food)

```swift
/// Look up food by barcode in local database
/// - Parameter barcode: Product barcode
/// - Returns: Food if found in local database, nil otherwise
func lookupBarcode(_ barcode: String) async throws -> FoodSearchResult? {
    guard let local = try localDatabase.lookupBarcode(barcode) else {
        return nil
    }

    // Map database source string to FoodSource enum
    let source: FoodSource =
        switch local.source {
        case "openFoodFacts": .openFoodFacts
        case "foundation", "sr_legacy": .local
        default: .local
        }

    // Parse serving options from JSON string
    let servingOptions = ServingOption.parse(from: local.servingOptions)

    return FoodSearchResult(
        fdcId: local.fdcId,
        barcode: local.barcode,
        name: local.name,
        brand: local.brand,
        source: source,
        caloriesPer100g: local.caloriesPer100g,
        proteinPer100g: local.proteinPer100g,
        carbsPer100g: local.carbsPer100g,
        fatPer100g: local.fatPer100g,
        fiberPer100g: local.fiberPer100g,
        category: local.category,
        servingSize: local.servingSize,
        servingOptions: servingOptions
    )
}
```
