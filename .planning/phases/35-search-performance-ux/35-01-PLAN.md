**Tech available:** SwiftUI, @FocusState (iOS 15+), Task cancellation
**Established patterns:** 200ms debounce timing, @Observable ViewModels

**Issue analysis:**
1. **Sluggish typing:** `onChange` creates a new Task per keystroke. Each Task sleeps 200ms then performs search. Tasks aren't cancelled when new input arrives, causing multiple concurrent searches. Fix: Cancel previous task before creating new one, check cancellation after sleep.
2. **No auto-focus:** FoodSearchSheet lacks @FocusState on search TextField. Other views (ProgramWizardStepViews, ServingInputView) already use this pattern correctly.
3. **Small tap target:** Amount TextField is only 100px wide (frame maxWidth: 100). The entire inputDisplayRow card should be tappable to focus the text field, following iOS HIG touch target guidelines (44pt minimum).
</context>

<task type="auto">
  <name>Task 1: Fix search debouncing with proper task cancellation</name>
  <files>JabTracker/Views/Nutrition/FoodSearchSheet.swift, JabTracker/ViewModels/FoodSearchSheetViewModel.swift</files>
  <action>
  **In FoodSearchSheet.swift:**
  1. Add `@State private var searchTask: Task<Void, Never>?` to track the debounce task
  2. Update the `onChange(of: viewModel.searchText)` handler to:
     - Cancel existing searchTask before creating new one: `searchTask?.cancel()`
     - Create new task that sleeps, checks `Task.isCancelled`, then calls performSearch
     - Assign to searchTask

  **Current (broken):**
  ```swift
  .onChange(of: viewModel.searchText) { _, _ in
      Task {
          try? await Task.sleep(nanoseconds: SearchTiming.debounceNanoseconds)
          await viewModel.performSearch()
      }
  }
  ```

  **Fixed:**
  ```swift
  .onChange(of: viewModel.searchText) { _, _ in
      searchTask?.cancel()
      searchTask = Task {
          try? await Task.sleep(nanoseconds: SearchTiming.debounceNanoseconds)
          guard !Task.isCancelled else { return }
          await viewModel.performSearch()
      }
  }
  ```

  This ensures only the most recent keystroke triggers a search after the debounce period.
  </action>
  <verify>
  1. Build succeeds: `./scripts/build.sh`
  2. Manual test: Type "apple" quickly - should see only one search (check logs), not 5 separate searches
  </verify>
  <done>Fast typing produces single debounced search, no UI lag during typing</done>
</task>
