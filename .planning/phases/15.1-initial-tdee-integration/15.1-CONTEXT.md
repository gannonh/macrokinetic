# Phase 15.1: Initial TDEE Integration - Context

**Gathered:** 2025-12-28
**Status:** Ready for planning

<vision>
## How This Should Work

**Progressive Disclosure for HealthKit:**
When a user creates their first goal, we detect that we need biometrics for TDEE calculation. Show a friendly pre-prompt explaining WHY we need HealthKit ("To calculate your personalized calorie targets"), then trigger the iOS HealthKit permission sheet.

If granted: pre-fill height, sex, DOB, and current weight from HealthKit. User can see and edit these values — if they change anything, it syncs back to HealthKit (if write permission was granted).

If declined: show manual entry fields as fallback. Never nag, but make it easy to change their mind later via Settings.

**TDEE Calculation Flow:**
Once we have height + weight + sex + DOB + activity level → calculate TDEE using TDEEService. Apply the calculated TDEE to derive calorie targets based on the user's goal (deficit for weight loss, surplus for muscle gain). Macro targets derive from program settings (diet preference, protein level, etc.).

**Program Summary Screen:**
After completing goal + program setup, users see a "Your macro program is ready" screen showing:
1. Weekly macro grid — visual breakdown of daily targets (Cals/P/F/C) by day of week, with colored rows (blue calories pill, orange protein, yellow fat, green carbs)
2. "How was your program designed?" explanation — numbered steps explaining:
   - Estimated Expenditure (TDEE): e.g., 1893 kcal
   - Average Target: e.g., 1436 kcal (based on weight loss rate)
   - (Macro splits based on program settings)

This screen appears after new goal creation, goal edits, and weekly check-ins (Phase 16).

**Recalculation Triggers:**
Target cals/macros recalculate each time:
- New goal is created
- Goal is edited
- Weekly check-in happens (Phase 16 will wire this up)

</vision>

<essential>
## What Must Be Nailed

- **Accurate TDEE calculation** — Getting the numbers right from biometrics + activity level using TDEEService
- **HealthKit integration** — Seamless read/write with Apple Health, graceful fallback if unavailable/declined
- **Program summary screen** — Clear visual showing calculated targets and explaining how they were derived
- **Fix Program Wizard blank screen bug** — Currently renders blank after Goal setup completes, breaking the entire flow

All four are equally critical — can't ship without all working together.

</essential>

<specifics>
## Specific Ideas

**Program Summary Screen Design (match reference):**
- Header: "Your macro program is ready"
- Weekly grid: 7 columns (M-S), 4 rows (Cals as blue pill on top, then P/F/C as colored rectangular cells)
- Colors: Blue (calories), Orange (protein), Yellow (fat), Green (carbs)
- Below grid: "How was your program designed?" with numbered explanation steps
- Bottom: "Done" button

**HealthKit Permissions in Settings:**
- Settings → Health Integration section
- Toggle per data type (Height, Weight, Sex, DOB)
- Separate read/write toggles where applicable
- "Import from Health" button for users who initially declined

**Smart Re-asking:**
- If user declined initially but later wants HealthKit data: Settings toggle or "Import from Health" button
- Never nag, but make it easy to change their mind

</specifics>

<notes>
## Additional Context

**Current State Issues:**
1. HealthKit integration exists but is WRITE-ONLY (syncs weight TO HealthKit). No READ from HealthKit for biometrics.
2. User.dailyCalorieGoal defaults to 2000 — TDEEService exists but is never called.
3. Program Wizard renders blank after Goal setup — critical bug breaking the flow.
4. Strategy view shows hardcoded default values instead of calculated targets.

**Existing Code to Leverage:**
- `TDEEService` — already built in Phase 14, just needs to be wired up
- `TDEECalculationEngine` — Mifflin-St Jeor formula implementation exists
- `WeightService+HealthKit.swift` — write-only integration, needs read functions added
- `User.heightCm`, `User.gender`, `User.dateOfBirth` — properties exist, just unpopulated

**HealthKit Data Types Needed:**
- `HKCharacteristicType.biologicalSex` → User.gender
- `HKCharacteristicType.dateOfBirth` → User.dateOfBirth
- `HKQuantityType.height` → User.heightCm
- `HKQuantityType.bodyMass` → import initial weight

</notes>
